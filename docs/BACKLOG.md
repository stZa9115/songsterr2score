## 1. [x] core 可被程式呼叫

現在的 `core.py` 只適合 CLI：找不到譜面時 `sys.exit`，檔名取自 HTML 檔名。

驗收：
- 解析失敗時丟出專用例外（CLI 在 `main()` 內接住並印出訊息後以非零碼結束），不可在函式庫程式碼內 `sys.exit`。
- 新增 `default_name(html)`，依 SPEC「譜名」規則回傳預設譜名；單元測試用小段 HTML 字串涵蓋：有 meta、沒有 meta 退回 `<title>`。

- 新增檔名清理函式，依 SPEC 規則；有單元測試。
- `convert()` 可接受譜名，輸出檔名為 `{譜名}_staff/_tab/_both`，PDF 內標題為該譜名；回傳輸出檔路徑與警告清單。
- CLI 新增 `--name`；未指定時使用預設譜名。
- 偵測不完整的頁面：Songsterr 只渲染畫面附近的譜行，其餘留下 `data-player-key="tab" data-line-unit-index="N"` 佔位元素。
  應有行數 = 佔位元素數；實際行數 = 不重複的 `multitrack-line-group-N` 數量。兩者不同時產生警告：
  「頁面只包含 X/Y 行譜，請用 tools/collect-songsterr.js 收集完整譜面」。
  `tools/collect-songsterr.js` 產生的檔案兩者相等（`samples/` 四份皆是），不可產生此警告；
  `samples/_orig/bass-propose.html` 是 Ctrl+S 存的不完整頁面（10/24 行），可用來測試會產生警告。
- 現有 golden 測試不需更新即通過（.ly 內的 title 若因此改變，屬預期變動，於 PR 說明後更新 golden）。

## 9. [ ] 格數辨識：最高音弦上的 3 被當成 5

使用者對照原譜發現：なつのうた 第 26、50、52、67、72 小節第一弦的 3 輸出成 5；OUTSIDER RODEO 也有類似情況（小節未記錄）。

已查明的原因：`classify()` 只靠輪廓段數分辨數字（16 段 = 3、14 或 15 段 = 5）。最高音弦上的 3 有時少了最後一段，
變成 15 段，就被當成 5。這個 15 段字形的前 15 段與正常的 3 完全相同，起點也相同（相對 bbox 約 (6.6, 7.4)），
真正的 5 起點約 (6.7, 6.5)。目前樣本中出現位置：
- なつのうた 第一弦：26、46、50、52、67、72 小節（46 不在使用者的清單中，應一併確認）
- Fear Of The Dark 最高音弦：62、63、66、67、70、71、74、75、79、83、87、91、107、145、170、178、219、223、239、243 小節
- OUTSIDER RODEO：沒有這個字形，使用者看到的可能是另一種錯法

驗收：
- 數字改以輪廓形狀判斷（例如比對起點與各段相對座標），不再只靠段數；上述小節的格數改為 3。
- 清查四份樣本所有格數字形：列出每種輪廓與判讀結果，確認沒有其他「同一形狀被判成不同數字」或「段數變異造成誤判」
  的情況；最高音弦與其他弦的字形都要看。清查結果寫在 PR 說明（只寫形狀特徵與小節編號，不貼譜面內容）。
- OUTSIDER RODEO：清查若找到誤判就修正；找不到時在 PR 說明列出最高音弦上所有格數為 5 的小節，請使用者對照原譜。
- 單元測試用合成的輪廓涵蓋「15 段的 3」與「正常的 5」，不可直接複製樣本中的路徑資料。
- 依 Golden 規則更新なつのうた（與プロポーズ，若有變動）的 golden，並在 PR 說明每個差異都屬於這個修正。

## 10. [ ] P.M.（Palm Mute，悶音奏法）記號

使用者要求，參考 OUTSIDER RODEO 第 62–65 小節。

頁面上的畫法（已確認）：每段 P.M. 在譜行 SVG 內是一個 `<g data-effect-run="palmMute-…">` 群組，含
`<text class="…_text">P. M.</text>`、一條虛線 `<line x1 … x2 …>`（範圍即涵蓋的音），以及結束處的一條短豎線。
跨行的一段 P.M. 會拆成每行各一個群組：沒有結束短豎線的群組表示延續到下一行。
`palmMute-0-N` 中的 N 看起來是該群組起點所在小節的 0 起算編號，但應以 x 座標對應音符為準。
OUTSIDER RODEO 共 3 個群組，構成 2 段：第 62–65 小節（跨兩行）、第 121–122 小節。

驗收：
- 解析出每段 P.M. 涵蓋的音符（依虛線的 x 範圍對應同一行的音符，跨行要接續）。
- LilyPond 的五線譜與 TAB 都在涵蓋範圍上方顯示「P.M.」加虛線延伸線，到範圍結束為止（例如 TextSpanner）。
- MusicXML 以 MuseScore 能顯示的方式輸出 P.M. 與其範圍（例如 `<direction>` 的 `<words>P.M.</words>` 搭配 `<dashes>` start / stop），並在 PR 說明選擇的理由。
- 單元測試以合成 HTML 涵蓋：單行一段、跨行一段、同一行有兩段。
- OUTSIDER RODEO 三種 .ly 能通過 LilyPond 編譯；PR 說明請使用者對照原譜檢查第 62–65、121–122 小節。
- 依 Golden 規則更新 OUTSIDER RODEO 的 golden，其他樣本不得變動。

## 11. [ ] 重音（accent）與斷奏（staccato）記號

使用者要求，參考 Fear Of The Dark。

頁面上的畫法（已確認）：與 P.M. 同樣是譜行 SVG 內的 `<g data-effect-run="…">` 群組，但每個群組只標一個音：
- 重音：`accent-…`，內含一條 `>` 形狀的路徑（`<path d="m{x}-11l9-3l-9-3">`）。
- 斷奏：`staccato-…`，內含一個圓點 `<circle cx=… cy="-14" r="2">`。

id 格式為 `{種類}-{音軌}-{小節}-{聲部}-{拍}`，其中小節是 0 起算（id 的 92 對應第 93 小節，已用 x 座標核對）。
應以 x 座標對應到同一行的音符（或和弦），id 只作為交叉檢查。
Fear Of The Dark 的分布（小節編號為 1 起算）：
- 重音 26 個：93、101、102、109、110、158、160、162、163、168、170、171、176、178、179、221、222、229、230、237、238
- 斷奏 29 個：129、133、137、141、160、162、163、164、166、168、170、171、172、174、176、178、179、180

驗收：
- 解析出每個重音與斷奏所屬的音符；一個音可同時有兩者。對應不到音符時產生繁中警告，不可靜默略過。
- LilyPond 五線譜與 TAB 都顯示記號（`->`、`-.`），兩種記號同時存在時都要顯示。
- MusicXML 以 `<notations><articulations>` 的 `<accent/>`、`<staccato/>` 輸出；和弦只標在第一個音上。
- 單元測試以合成 HTML 涵蓋：單一音符的重音、單一音符的斷奏、和弦上的記號、同一音同時有兩種記號。
- Fear Of The Dark 三種 .ly 能通過 LilyPond 編譯；在 PR 說明列出輸出中每個記號所在的小節，數量與上列相符（26 / 29），請使用者對照原譜抽查。
- Fear Of The Dark 目前沒有 golden，不需產生；其他樣本的 golden 不得變動。
