# 待辦清單

## 1. [x] core 可被程式呼叫

現在的 `core.py` 只適合 CLI：找不到譜面時 `sys.exit`，檔名取自 HTML 檔名。

驗收：
- 解析失敗時丟出專用例外（CLI 在 `main()` 內接住並印出訊息後以非零碼結束），不可在函式庫程式碼內 `sys.exit`。
- 新增 `default_name(html)`，依 SPEC「譜名」規則回傳預設譜名；單元測試用小段 HTML 字串涵蓋：有 meta、沒有 meta 退回 `<title>`。
  另以 `samples/` 驗證四份樣本的預設譜名（沒有樣本時跳過）。
- 新增檔名清理函式，依 SPEC 規則；有單元測試。
- `convert()` 可接受譜名，輸出檔名為 `{譜名}_staff/_tab/_both`，PDF 內標題為該譜名；回傳輸出檔路徑與警告清單。
- CLI 新增 `--name`；未指定時使用預設譜名。
- 偵測不完整的頁面：Songsterr 只渲染畫面附近的譜行，其餘留下 `data-player-key="tab" data-line-unit-index="N"` 佔位元素。
  應有行數 = 佔位元素數；實際行數 = 不重複的 `multitrack-line-group-N` 數量。兩者不同時產生警告：
  「頁面只包含 X/Y 行譜，請用 tools/collect-songsterr.js 收集完整譜面」。
  `tools/collect-songsterr.js` 產生的檔案兩者相等（`samples/` 四份皆是），不可產生此警告；
  `samples/_orig/bass-propose.html` 是 Ctrl+S 存的不完整頁面（10/24 行），可用來測試會產生警告。
- 現有 golden 測試不需更新即通過（.ly 內的 title 若因此改變，屬預期變動，於 PR 說明後更新 golden）。

## 6. [ ] golden 改以雜湊提交，跟著分支走

問題：`samples/golden/` 被 gitignore，所有分支共用同一份。某個分支更新 golden 後，切到其他分支跑測試就會失敗
（PR #7 時發生過），多個 PR 同時開著時 Stop hook 會一直擋。

驗收：
- 新增提交進 repo 的 `tests/golden.json`：`{樣本 stem: {輸出檔名: sha256}}`。雜湊不含版權內容，可以提交。
- `test_golden` 以雜湊比對；`samples/golden/` 的完整檔案保留為本機選用，不一致時若有完整檔就附上前幾行 diff 協助判讀。
- `UPDATE_GOLDEN` 的用法不變，同時更新 `golden.json` 與本機完整檔。
- 有樣本但 `golden.json` 沒有該樣本 → 跳過（與現在相同）；`golden.json` 有但本機沒有樣本 → 跳過。
- 由目前 `samples/golden/` 產生初始 `golden.json`，產生前先確認現有 golden 測試在 `main` 上全綠。
- 切到另一個分支、改一行會影響輸出的程式碼，確認測試失敗；切回來確認通過（在 PR 說明記錄這個手動驗證）。
- 更新 CLAUDE.md 的 Golden 規則。

## 9. [ ] 格數辨識：最高音弦上的 3 被當成 5

使用者對照原譜發現：なつのうた 第 26、50、52、67、72 小節第一弦的 3 輸出成 5；OUTSIDER RODEO 也有類似情況（小節未記錄）。

已查明的原因：`classify()` 只靠輪廓段數分辨數字（16 段 = 3、14 或 15 段 = 5）。最高音弦上的 3 有時少了最後一段，
變成 15 段，就被當成 5。這個 15 段字形的前 15 段與正常的 3 完全相同，起點也相同（相對 bbox 約 (6.6, 7.4)），
真正的 5 起點約 (6.7, 6.5)。目前樣本中出現位置：
- なつのうた 第一弦：26、46、50、52、67、72 小節（46 不在使用者的清單中，應一併確認）
- Fear Of The Dark 最高音弦：62、63、66、67、70、71、74、75、79、83、87、91、107、145、170、178、219、223、239、243 小節
- OUTSIDER RODEO：沒有這個字形，使用者看到的可能是另一種錯法

驗收：
- 數字改以輪廓形狀判斷（例如比對起點與各段相對座標），不再只靠段數；上述小節的格數改為 3。
- 清查四份樣本所有格數字形：列出每種輪廓與判讀結果，確認沒有其他「同一形狀被判成不同數字」或「段數變異造成誤判」
  的情況；最高音弦與其他弦的字形都要看。清查結果寫在 PR 說明（只寫形狀特徵與小節編號，不貼譜面內容）。
- OUTSIDER RODEO：清查若找到誤判就修正；找不到時在 PR 說明列出最高音弦上所有格數為 5 的小節，請使用者對照原譜。
- 單元測試用合成的輪廓涵蓋「15 段的 3」與「正常的 5」，不可直接複製樣本中的路徑資料。
- 依 Golden 規則更新なつのうた（與プロポーズ，若有變動）的 golden，並在 PR 說明每個差異都屬於這個修正。
